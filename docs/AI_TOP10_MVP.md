# AI 今日必看 Top10 · MVP

## 产品目标

保留 NewsNow 原有热榜、移动端交互与 PWA，首页上方增加可折叠的 **AI 今日必看 10 条** 区域。用户无需登录即可浏览热点；仅在主动展开 AI 区域时请求生成结果。

> 当前仅开发了第一版代码；本分支还没有完成真实模型端到端验证、生产部署和手机验收。

## 技术实现

- 页面：`src/components/ai-highlights.tsx`，集成在 `src/routes/index.tsx`
- Nitro 接口：`GET /api/ai/top10`，代码位于 `server/api/ai/top10.ts`
- 数据：复用 NewsNow 内置数据源 getter；优先读取已有缓存，单个数据源失败不会阻断其他数据源
- 候选：目前选取微博、知乎、今日头条、抖音、华尔街见闻、36氪、联合早报及 AIHOT 等 8 个来源，最多 100 条标题
- AI：调用兼容 OpenAI Chat Completions 的服务，要求 JSON，最多 10 个不同事件
- 校验：模型只能引用输入候选 ID；最终新闻链接必须匹配可信候选数据，不能由模型自造
- 缓存：进程内 30 分钟，单进程内并发请求共享一次生成；生成失败时返回已有旧结果（若存在）
- 降级：若未配置 API Key，前端展示“尚未配置或暂时不可用”，原热榜继续正常运行

## 配置

将以下内容配置为**服务端环境变量**，不要写入代码或带 VITE_ 前缀，也不要把真实密钥提交到 GitHub：

```env
AI_NEWS_API_KEY=
AI_NEWS_MODEL=gpt-4o-mini
AI_NEWS_BASE_URL=https://api.openai.com/v1
```

建议先用兼容 OpenAI Chat Completions API、支持 `response_format: { "type": "json_object" }` 的模型测试。不同服务商并非全部兼容上述响应格式。

本地可配置于不纳入 Git 版本控制的 `.env.server`。云端需要使用平台 Secrets / Environment Variables 进行设置。

## 内容质量边界（必须保留）

- **当前仅有榜单标题**，因此 AI 生成的是标题级摘要，不是阅读原文后的新闻综述。
- 模型不得补充没有被来源证实的时间、数字、引述、事件细节。
- “为什么重要”只表示潜在影响，不能描述成已经发生的事实。
- 对热点判定为同一事件时，要求引用至少一个来自输入候选的原始链接。
- 排序权重是初始产品假设：跨平台热度 30%、社会影响 25%、事件重要度 20%、时效性 15%、信息价值 10%；当前权重作为模型说明，而不是可复现的数学打分。后续应实现独立打分器和更严格的事件聚类。

## 已知局限 / 上线前阻断项

1. 需要真实 Key 和模型联调，验证数据源 ID、Cloudflare 环境变量读取、部署产物及响应 JSON。
2. 需运行 `pnpm install`、`pnpm typecheck`、`pnpm lint`、`pnpm test` 和 `pnpm build`，并处理出现的兼容问题。
3. **费用风险：** 当前 API 为公开按需生成，只有单进程短期缓存；多实例/冷启动或恶意请求可能重复触发付费调用。生产部署前必须增加持久缓存、请求频控以及服务端 AI 用量上限，推荐改为可信定时任务预生成、公开 API 仅提供缓存。
4. 聚类基于模型而不是独立的稳定规则；同一事件仍可能重复。
5. 8 个初始来源不覆盖全网；NewsNow 各源的可用性、引用合法性与用户所在地区访问结果可能不同。
6. 尚未实现对新闻正文的可信提取或交叉核实，因此不能把摘要宣传为“事实核验后摘要”。
7. PWA 仍使用 NewsNow 原有配置；产品名和图标尚未定制。

## 开发协作

以该 GitHub 仓库为唯一代码来源。ChatGPT 在功能分支提交更改并发起 PR；用户只在必要时连接部署平台、保存 API 密钥或测试手机体验。不要把 API Key 直接贴在聊天中。

## 推荐验收标准

1. AI 面板位于首页原榜单上方；关闭后完整保留原有热榜交互。
2. 无 Key / 某一数据源不可用 / AI 请求失败时，原有热榜不受影响，错误提示清晰。
3. 10 条推荐不包含显著重复事件、包含重要度及谨慎表述的梗概。
4. 每条至少一个可点击的原始热榜链接，不允许出现模型凭空生成的 URL。
5. 多次打开在缓存期内不重复产生模型费用。
6. 部署后通过手机浏览器添加到主屏幕，检验启动与滑动行为。
